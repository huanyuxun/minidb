# 架构与事务设计

## 分层

```text
CLI / C++ Database、Connection、PreparedStatement、ResultSet
             |
Lexer -> Parser -> AST -> 目录绑定 / 查询规划
             |
Init / Next / Close 执行器 -> HeapFile / BPlusTree
             |
事务私有页面 -> Pager / WAL -> BufferPool / DiskManager
             |
platform::File -> Windows API / POSIX
```

SQL 语法由独立词法分析器和递归下降分析器处理，不使用示例字符串匹配执行 SQL。AST、值类型和表达式求值位于 `sql.hpp` / `sql.cpp`。页面、元数据、记录和索引均以显式字节编码持久化，磁盘中不保存 C++ 指针或原生对象布局。

`Database` 持有共享数据库状态；每个 `Connection` 持有自己的事务上下文。`ResultSet` 将结果物化到内存。查询算子公开 `Init()`、`Next()`、`Close()`，包含过滤、投影、排序、限制和嵌套循环连接。当前扫描和部分中间结果会物化，不能把执行器接口等同于全流程流式、常量内存执行。

查询绑定会检查列名、歧义引用、函数参数、聚合嵌套和 GROUP BY 约束；空表也必须通过这些检查。单表 WHERE 中可使用索引的 AND 比较条件被合并为上下界，剩余条件仍由 Filter 完整求值。混合 INTEGER/DOUBLE 条件只有在键转换不会改变结果时才使用索引，否则保留扫描以避免大整数精度损失。JOIN 当前按 SQL 指定顺序执行嵌套循环。ORDER BY 可以引用输出别名或输出列位置；用于排序但未投影的值作为内部临时列处理，返回前删除。

## 物理数据组织

页面大小 4096 字节，前 32 字节是通用页头。页头携带页面类型、页 ID、LSN 和校验信息。`DiskManager` 负责页面 I/O；`BufferPool` 缓存已提交页面，以 LRU 驱逐、pin count 和 RAII `PageGuard` 管理占用。可配置缓存帧数；访问受同步机制保护。

Heap 使用链接的 slotted pages；稳定 slot ID 与页 ID 组成 RID。删除空间会压实复用，变长更新无法原位容纳时迁移到新 RID。索引维护与记录更新属于同一个事务。

B+ Tree 的内部节点、叶子节点、分隔键和叶子链均存储在页面中。支持分裂、删除后的合并或重分配、根收缩和范围扫描。非唯一索引使用键与 RID 的组合顺序，允许重复键跨多个叶子页。根 ID 变化由目录在同一事务内保存。

## 并发和隔离

采用数据库粒度严格两阶段锁。读事务获取共享锁，写事务获取排他锁；锁保持到提交或回滚。多个只读连接可以并行；写事务之间及写事务与读事务之间互斥。

这是粗粒度、可串行化的锁定策略：显式读事务持有共享锁期间，其他事务无法改变数据库，因此不会出现不可重复读或幻读。它不提供 MVCC、快照隔离、行锁或写事务并行。

共享锁升级到排他锁可能形成等待环。锁管理器采用有限等待超时；超时事务整体回滚并释放全部锁，其他事务才能继续。该策略解除死锁，但没有构建等待图进行主动死锁检测，也不保证选择代价最小的受害者。等待写者会阻止新读者插队；超时仍可能发生于长事务。

## 原子性和恢复

写入先进入事务私有页面集合，未提交页面不进入可刷盘缓冲池，即 no-steal。回滚丢弃私有页面与目录状态，无需修改已经持久化的用户数据。正常提交将完整页面 after-image 和提交记录写入 WAL 并同步，然后才允许数据页刷盘；因此 WAL 顺序规则直接成立。

重启扫描 WAL，根据完整且有效的提交记录确认事务，只重做已提交事务。完整页映像可以修复提交后数据页写入中断；相同映像重复重做不改变逻辑结果。未提交尾部不能成为用户数据。Checkpoint 先保证数据文件已同步，再裁剪已不需要的 WAL。格式、故障点及精确损坏处理见 [存储文档](storage.md)。

该方案选择正确性和可审计性，代价是完整页日志、提交刷盘和大事务的内存占用。它没有 ARIES 的脏页表、事务 undo 链或 fuzzy checkpoint。恢复承诺基于操作系统同步调用和正常存储设备；测试模拟进程中断，不能替代物理断电及故障硬件认证。

## 生命周期与错误

OS 句柄、页面固定和连接事务使用 RAII。数据库文件受到进程间排他锁保护，防止两个不协调实例同时打开写入。平台差异集中在 `platform.cpp`；性能程序的内存探针独立封装，不进入引擎逻辑。

语法、类型、约束、锁超时、I/O 和损坏问题通过异常报告。查询结果和 SQL 支持说明应以实际测试为准；磁盘校验发现损坏不意味着具有任意数据恢复或自动修复能力。
